导出和导入 jvmguard 配置有几种不同的动机：

* **备份**：定期备份 jvmguard 服务器配置是个好做法。配置中包含大量关于事务及其预期行为的知识。它是一份
有价值的数据，可以存入版本控制系统。
* **预发**：如果有预发环境，在其中试验 jvmguard 配置的更改然后再部署到生产服务器，就需要一种在 jvmguard
安装之间传输配置的方式。
* **无人值守部署**：将 jvmguard 服务器部署到远程机器时，可以使用 jvmguard 的无人值守安装模式，将其安装在
尚未安装过 jvmguard 服务器的服务器实例上。在这种情况下，必须将导出的配置放在安装程序旁边。

## 服务器配置

管理员可以进入常规设置并选择“导入 / 导出”选项卡。整个配置会导出为一个 JSON 文件。导入该文件时，整个
服务器配置都会被替换。更改在点击**保存**之前不会生效。无法通过这种方式删除当前用户。

<Figure src="ui/config_export_server.png" />

JSON 文件格式带有版本号，较新的 jvmguard 服务器可以读取旧版本导出的文件。

将该文件命名为 `jvmguard_server_config.json` 并复制到 jvmguard 数据目录，会在启动时覆盖整个配置。
[无人值守安装](/docs/zh-cn/config/unattended-installations)就使用了这种机制。导入完成后，该文件会被自动
删除。

## 记录配置

包含整个配置的导出 JSON 文件含有用户数据。这对于预发甚至备份场景来说可能并不合适。在记录设置中，还可以
导出选定的 VM 组配置。在这里可以选择“所有 JVM”或某个特定的 VM 组，然后点击右侧的导出按钮。

此导出不仅对管理员可用，对拥有“分析员”访问权限的用户也可用。

将该文件命名为 `jvmguard_recording_config.json` 并复制到 jvmguard 数据目录，会在启动时覆盖整个记录配置。
导入完成后，该文件会被自动删除。
