임계값은 텔레메트리에 대한 이상 상태를 감지합니다. 임계값 위반은 어떤 액션과도 직접 연결되지 않고 **연결된
카운터를 증가**시킬 뿐입니다. 임계값은 단일 VM 또는 VM 그룹에 대해 구성할 수 있습니다. 이것은 단일 VM이
아닌 항상 VM 그룹 수준에서 작동하는 [트리거](/docs/ko/main/triggers)와는 다릅니다.

**단일 VM 임계값**의 경우 각 VM의 텔레메트리 값이 검사되고 위반하는 각 VM에 대해 임계값 위반이 생성됩니다.
예를 들어, 사용된 힙에 상한이 있고 그 이상을 사용하는 각 VM이 자체 임계값 위반을 갖게 됩니다.

**VM 그룹 임계값**의 경우 VM 그룹의 텔레메트리 값이 검사되며 개별적으로 임계값을 위반하는 VM이 몇 개든
하나의 임계값 위반만 생성됩니다. 그룹에 10개의 VM이 있고 모든 VM에서 힙 사용량이 증가하는 경우를 생각해
보세요. 단일 VM 임계값을 사용하면 10개의 VM 모두가 임계값 위반을 보고합니다. 결국 한 번만 반응하면 되지
열 번 반응할 필요는 없습니다. 또한 평균화된 그룹 값이 더 매끄러우므로 단일 VM 임계값보다 허위 임계값 위반이
적게 발생합니다.

빈도 데이터를 보여 주는 모든 텔레메트리는 VM 그룹에 대해 합산됩니다. 각각 초당 10개의 트랜잭션을 처리하는
10개의 VM이 있는 경우 VM 그룹은 초당 100개의 트랜잭션을 표시합니다. 허용 가능한 범위가 단일 VM의 부하가
아닌 총계 값에 대해 정의된 경우 임계값을 VM 그룹 임계값으로 구성해야 합니다.

<Figure src="threshold_groups.svg" />

카운터는 단일 VM 임계값의 경우 VM 단위로, VM 그룹 임계값의 경우 VM 그룹 수준으로 유지됩니다. 임계값 위반이
발생하면 부모 계층 구조를 따라 올라가며 연결된 모든 카운터를 1씩 증가시킵니다. 해당 계층 구조의 각 VM
그룹에서 해당 수의 임계값 위반에 반응하는 트리거를 정의할 수 있습니다.

## 구성

VM 그룹의 기록 설정에서 각 텔레메트리에 대한 임계값을 정의할 수 있습니다. 임계값 정의에는 연결된
텔레메트리와 선택적 **하한 및 상한**이 있습니다. 사용 가능한 단위는 텔레메트리 선택에 따라 달라집니다.

경우에 따라서는 예를 들어 서로 다른 심각도를 지정하기 위해 동일한 텔레메트리에 대해 여러 임계값 정의가
필요합니다. 이 경우 "높은 힙 사용량" 및 "매우 높은 힙 사용량"과 같이 임계값에 **서로 다른 사용자 정의
이름**을 지정해야 합니다. 이러한 정의는 서로 다른 에스컬레이션 전략을 가진 트리거의 기준으로 사용할 수
있습니다.

임계값 위반의 허위 실행을 방지하기 위해 임계값 위반이 감지되기 전에 한계가 초과되어야 하는 최소 시간을
구성할 수 있습니다. 임계값이 실행된 후에는 임계값이 음소거되어 다시 실행될 수 없는 억제 시간이 있습니다.
이는 진동하는 상태에서 빈번한 실행을 방지하는 역할을 합니다.

<Figure src="threshold_inhibit.svg" />

임계값이 계속 위반되면 jvmguard는 해당 시간 동안 더 이상 임계값 위반을 실행하지 않습니다. 이 제약을
비활성화하는 확인란이 있습니다. 비활성화하면 구성된 억제 시간을 주기로 일정한 속도로 새 임계값 위반이
실행됩니다.

트랜잭션과 마찬가지로 임계값 세트를 저장하고 로드할 수 있습니다. 이를 통해 VM 그룹 구성 간에 임계값 정의를
복사하여 붙여넣을 수 있습니다.
