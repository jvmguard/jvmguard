アプリケーションがすでにOpenTelemetryまたはMicrometerのトレーシングアノテーションを使用している場合、
jvmguardは追加の設定なしでそれらをトランザクションに変換できます。"OTel"トランザクションタイプは次を
マッピングします:

* メソッドの `io.opentelemetry.instrumentation.annotations.WithSpan`
* メソッドおよびクラスの `io.micrometer.observation.annotation.Observed`

これらのアノテーションは、OpenTelemetryまたはMicrometerを使用するアプリケーションでは、トレーシング
バックエンドが接続されていなくてもすでに存在していることがよくあります。`@WithSpan`はOpenTelemetry
エージェントまたはSpringスターターがある場合にのみ有効になり、`@Observed`はクラスパスにMicrometer AOP
がある場合にのみ有効になるためです。jvmguardはアノテーションを名前だけで一致判定するため、
アノテーションが機能している必要はなく、使用されていない場合のオーバーヘッドもありません。

トランザクション記録設定の"OTel"タブには、事前設定されたOTelトランザクション定義があります。他の
トランザクション定義と同様に、編集、並べ替え、破棄、削除が可能です。削除しても再作成されません。

## 命名

デフォルトでは、トランザクションはアノテーションのスパン名属性(`@WithSpan`では`value`、`@Observed`では
`contextualName`)で命名されます。属性が空の場合、トランザクション名は`ClassName.methodName`になります。
これはOpenTelemetry自体のデフォルトのスパン名でもあります。"命名"タブで、他のトランザクション定義と
同様に命名を変更できます。

## スパン名によるフィルタリング

OTelトランザクション定義の"フィルター"タブには、クラスフィルターに加えて"スパン名"フィールドがあります。
スパン名が設定されたワイルドカードまたは正規式に一致するアノテーションのみがトランザクションを生成します。
スパン名属性のないアノテーションはスパン名フィルターに一致しません。

## 他のトランザクションタイプとの重複

メソッドはサポートされるアノテーションを複数持つことができます。重複するトランザクションを避けるため、
次のルールが適用されます:

* メソッドに`@MethodTransaction`アノテーションがある場合、宣言型トランザクションのみが作成されます。
* メソッドに`@WithSpan`と`@Observed`の両方がある場合（メソッド自体、または外側のクラスのクラスレベルの`@Observed`を介して）、`@WithSpan`のトランザクションのみが作成されます。
* メソッドに直接付けられたアノテーションは、外側のクラスのクラスレベルの`@Observed`より優先されます。
